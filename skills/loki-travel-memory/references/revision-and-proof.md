# 改旧片必须证明观感变化

先检查旧片和工程，保存基线。用户说“没提升”是一条结果证据，不是用户没看到细节；不要用代码改动量解释。

## 诊断四类问题

1. 内容层：遗漏事件、误地名、好照片没用、同期声未说完。优先修事实和覆盖，换底板解决不了。
2. 关系层：图组互不关联、没有主图、视频播放后莫名交换位置。重新分组和观看顺序，不能只换动画。
3. 节奏层：静止过久、快闪、多个焦点同时飞、歌曲提前。重新剪时长、焦点和声音边界，不能只套淡化。
4. 表现层：文字层级、对比、裁切、调色、图框。保留已认可方向做局部设计，不能把视觉翻新当全部升级。

为本轮挑最影响体验的问题，不固定凑数量。每项写成：旧版时间点/事件 → 看到的问题 → 打算改变的观看体验 → 修改 → 新版对应点 → 证据 → 结论。其他反馈留在待办，不忘记也不借机全部推翻。

## 可感知变化的证据

同一个事件提供前后静帧和带上下文的连续片段，真实音乐一致或清楚标注音轨变化。改图组就展示观看顺序变化；改音频就给实际混音；改转场不能拿首尾静帧证明。

- 新版是更容易看清食物/人物，还是仅改变了边框？
- 新主图有没有比旧图更值得长停？替换是否真的增加信息？
- 眼睛是否自然从旧焦点到新焦点，中间有无抢动、遮景？
- 乐句、字尾和声音场景是否完整衔接，而不是形式上“不重叠”？
- 原本认可的画幅、底板、事实、音乐用途和字幕是否退步？

文字说明声称升级，但对照看不出来：标为未证明，不扩大到全片。大变样但主体更小或观感更乱：回到基线，保留有效局部，不继续叠效果。没有审美判断能力的自动测试不能给“审美提升通过”。

## 把反馈改成可执行记录

每条意见附：类别、适用范围（当前照片/事件/项目/用户长期偏好/通用约束）、证据、动作、验证方式、状态。口述纠正覆盖旧猜测，保留替代关系。用户选了 B，锁住所选 source_id；不能再以“换个更好看”偷偷替掉。

例如“花字跟图走”不能只记成文字偏好：把花字绑定对应媒体/场景节点，在同一合成层退出，核查最终视频的退出前/中/后帧。具体秒点只属于当前片，不进入全局模板。

## 人的参与边界

事实纠正、指定替换候选和已否定方向属于必须遵守的约束。普通裁切与合理调色默认自主做；只有确实存在品味分歧才给少量候选。一次局部修正无需反复请求整片授权。反馈后先把相关修改验证好，再交给用户看；不要让用户反复指出同一个基础错误。
