# 验收与跨旅行复用

## 五种结论分开写

1. 技术：文件可解码/播放、引用可恢复、画幅与字幕输出正确。
2. 规则：时间线审计、无未解释的重复和抢声、所有权退出检查。
3. 视觉：实际看过哪些静帧、哪些连续区间；主体、主次、动态中间态、字底对比与调色。
4. 声音：实际听到的输出文件/版本与范围、审阅方式、完整语义/字尾/歌曲余韵/音量变化。无法听到则未通过；播放命令成功不算听审。
5. 用户：事实、品味和记忆意义是否被认可。用户没回复不是通过。

这五项不能互相替代。审计通过只输出“规则检查通过”。质量失败先修复；工具限制保留待验收标记，提供需要听看的精确区间，不能反复转嫁本可自行检查的基础错误。

## 最后看实际导出文件

所有换曲、同期声进出、连续说话、指物句、动作结尾、片尾，以及每个复杂转场，都要有带前后文的审查片段。先听/看上下文，再回放局部；只听一个剪口瞬间可能漏掉上一句余韵。完整观看一遍检查跨段疲劳、重复、音乐映射与行程逻辑。发生混音或时间改变后重查受影响范围，再检查整片连续性；音轨哈希一致仅证明未改音，不继承不存在的听审结论。

字幕逐句对原声；低置信专名用地点证据或询问，不拿 ASR 当真相。实在听不明不编字。花字同步看退场前帧、退场帧与后帧，转场看中间态；布局查看实际成片尺寸，不只看大画布。

## 判断 Skill 是否真能迁移

不要把已反复训练过的一趟旅行当作跨场景验证。一次真正的迁移测试应使用未参与规则形成的、获授权的素材，保留原始简报，让执行者按公开包开始，不喂长白山的预期答案。可先完成一个代表片段，不必全片渲染。

| 测试类型 | 应观察的行为 | 不合格表现 |
|---|---|---|
| 新城市逛吃，照片多、无完整行程 | 从时间/内容恢复餐次和地点，设计食物与街景关系 | 换城市名仍套冰雪底板、用同组三张凑宫格 |
| 家庭旅行，互动声重要 | 保留动作反应和句子，少量询问身份及记忆价值 | 自动煽情、全程MV盖住家人说话 |
| 演出禁止拍摄，仅入场和谢幕 | 用真实现场证据建立事件，承认没有表演画面 | 生成/借别场演出冒充现场 |
| 旧片升级，已有喜欢的设计 | 对同事件诊断并提供可播放前后对比 | 只改代码、换底板或加装饰声称升级 |
| 不会听音的宿主 | 提前说明、完成可验证部分，安排必要听审 | 宣称全片听过或反复交“通过版” |

记录事实错误、遗漏事件、主体遮挡、重复基础问题、需要用户决定的数量、修改轮数、执行时间和最后接受状态；没有测到的填 unknown，不预设分数/成功率。表格推演不叫真实影片测试，不能宣传“任意模型拿来都好用”。

## 创作自由与底线

只约束伤害信息表达的行为，不把“只能一种转场”“不能提前入声”“必须圆角”写成电影通则。声音 J-cut 可用于上下文连续的同事件；指物句不能指错画面；跨歌曲提前进入需真实内容桥梁和听感证据。主焦点清楚时背景轻动可以存在，不能把所有层冻结当作高级设计。

首次使用者可只提供素材路径与发布用途。AI 应先做清点和推荐，问题随着素材暴露再集中提出；不强迫先填长问卷。只有真实缺失或用户要求才停在确认处。好的 Skill 应减少重复纠错与选择负担，而非增加一堆必须交作业的表。
